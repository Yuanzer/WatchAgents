# Watch4 语音转文字 — 侦察结论(2026)

来源:子代理精读 voice 子系统代码。

## 关键事实
- `AgentHoldToTalkVoice.kt`:按住说话 UX 状态机(Idle/Listening/Finalizing/Finished/Error),长按触发、停顿累积继续听、松手才提交。**纯框架 API,无 hook/overlay 依赖,可直接复用**,只需把后端从 SpeechRecognizer 换成真实 ASR 引擎。
- `SystemSpeechRecognizer.kt`:RecognitionService 发现工厂。无任何服务时 create() 返回 null(不抛异常)。
- `RecognitionService.kt`:**没有任何 ASR 引擎**,只是再代理系统 SpeechRecognizer(注释自证"委托给外部 ASR")。→ 手表端内置转文字**不需要它**,也不能靠它独立工作。
- `VoiceInteractionService/Session/SessionService`:系统数字助理角色(需注册为默认助理+BIND_VOICE_INTERACTION),手表版舍弃。
- `AssistantOverlayService` + `VoicePanel`:全屏 overlay 助理窗(依赖 AccessibilityService 截屏+LLM 栈),舍弃。
- 代码库内 grep 无 AudioRecord/MediaRecorder:无现成音频采集/格式封装。

## 可行路线(二选一或组合)
1. **端侧离线 ASR(最稳,不依赖 GMS/华为)**:sherpa-onnx 或 Vosk 中文小模型,ARM64 原生库 int8,约 40-80MB。AudioRecord 采集 → 引擎流式 partial/final。改造点:新增 LocalAsrEngine 替换 SpeechRecognizer 后端,UI 状态机复用 AgentHoldToTalkVoice/AgentVoiceInput。
2. **云端 ASR(网络可用时)**:MediaRecorder 采集 → OkHttp(可复用 AgentHttpClient)POST 云端 ASR。需自备 ASR 服务/Key。

## 决定(待与用户确认后最终拍板)
- 缺省选路线 1(端侧 sherpa-onnx)以保证"内置转文字"无外部依赖;手表 2GB 内存/低算力需用小模型(sherpa-onnx zipformer int8 中文 ~30-60MB 或 vosk-small)。
- 保留 queries 中 RecognitionService 发现,若系统(华为)存在可用 ASR 服务则优先系统(质量好、零包体),否则自动落到端侧引擎。

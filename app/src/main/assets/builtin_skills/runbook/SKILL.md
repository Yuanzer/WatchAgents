# Runbook（常见问题手册）

为 WA 维护一份可复用的故障排查手册，把"踩过的坑"变成"下次不用再踩"。

## 何时记录

在以下情况稳定后，把经验写入 runbook：

1. 同一问题在本次会话或过往会话中再次出现（重复犯错）
2. 排查花费了多轮工具调用或多次试错才解决
3. 用户明确说"这个问题记一下""下次注意""别再犯"
4. 发现一个可复用的修复步骤或规避方案

## 默认存储

- runbook 章节：长期记忆（`MEMORY.md`）中的 `# Runbook` 段落；如需保留更完整的排查过程与长日志，可同时用 `files_write` 把过程写入工作区（如 `runbook/问题名.md`），记忆里只留索引与结论
- 与 self-improving-agent 分工：后者沉淀通用教训，runbook 只保留验证过的结论
- 首条写入前先 memory_get 查看是否已有 `# Runbook` 章节，没有则用 memory_write append 创建

## 条目格式

每条记录包含：

```markdown
## <问题一句话摘要>

- **现象**：用户看到的或工具报出的表现
- **原因**：根因（命令、配置、权限、设备状态等）
- **修复**：验证过的解决步骤，按顺序列出
- **预防**：如何避免再次发生
- **标签**：`#voice` `#search` `#memory` `#model` 等
```

## 工作流

1. 先稳定当前用户可见的任务，再补记 runbook
2. 写入前先 memory_search/memory_get 定位 `# Runbook` 章节，若已有相同条目则更新"修复/预防"而不是新增重复条目
3. 同类问题再次出现时，先语义检索 runbook 再试新方案
4. 条目稳定后（跨会话复现过或验证过），promote 到 `# 核心记忆` 之外的稳定章节

## 输出纪律

- 只记录验证过的结论，不记录猜测
- 包含具体命令、路径、错误码，不写"可能是权限问题"这类模糊描述
- 不写入密钥、验证码、个人敏感数据
